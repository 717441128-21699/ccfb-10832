# 地址解析与分拣编码工具（纯浏览器端 · 地址库不出本机）

面向快递分拣中心的面单地址解析工具：把寄件人手写的、缺级别、含错别字/同音字/简称/繁体的
自由文本地址，拆成 **省 / 市 / 区 / 街道 / 小区 / 楼栋门牌**，给出每级置信度，并按可可视化
编辑的规则映射到分拣格口。全部计算在浏览器本地完成，地址库与数据只存 IndexedDB，**无任何网络请求**。

## 技术栈

- TypeScript + Vue 3 + Vite
- 纯前端：地址库 / 规则存 IndexedDB，批量解析跑在 Web Worker
- 核心解析引擎（`src/core`）与 UI 解耦，可在 Node 直接跑基准

## 快速开始

```bash
npm install
npm run dev        # 浏览器打开本地地址
npm run build      # 生产构建（含 vue-tsc 类型门禁）
npm run typecheck  # 类型检查（含 .vue）
npm run selftest   # 确定性核心能力自测（13 项）
npm run bench 200000 42 both   # 20 万条双档位基准（数量、种子、档位可调）
                              # 档位：realistic 真实分布 / stress 激进压测 / both
```

## 解析引擎原理（src/core/parser.ts）

1. **文本规范化**：全角→半角、繁体→简体、噪声标点清洗、别称补全（`normalize.ts`）。
2. **门牌抽取**：先抽出 `X号楼/栋/幢/座/号 + 单元 + 房号`，避免数字干扰名称匹配。
3. **第一遍 · 精确扫描**：首字倒排索引在窗口内取所有 名称/别名/历史名 命中，
   做子串误命中过滤，再按 **父子链一致性 + 位置单调** 选出一条最连贯的锚点链；
   小区在街道未定时延迟，防止同名小区反推锁死错误街道。
4. **行政级模糊补全 + 区县复核**：省/市/区缺失时，在已知祖先子树内做同音/形近/编辑距离匹配；
   对短别名区锚点做同位置模糊复核，纠正子串误命中。
5. **街道/小区补全**：严格祖先作用域；缺区的同名路用小区锚点投票消解。
6. **缺失回填**：沿已命中节点的祖先链补全省/市/区，标注 `inferred` 并给较低置信度。
7. **置信度**：综合各级命中方式（精确 > 别名 > 历史 > 模糊 > 推断）、同名歧义惩罚、
   缺失级别惩罚，得到 0~1 的整体置信度。

### 模糊匹配为什么快

`LibraryIndex` 为每个级别建了 **同音字键 / 形近字键 / 核心名键 / 前缀键 / n-gram 块** 多套倒排：
查询先按键 O(1) 召回小候选集，编辑距离只在候选集上计算，避免全库 O(n) 比对。
实测吞吐约 500~900 条/秒（单线程 Worker）。

## 准确率口径（npm run bench）

测试面单由 `tools/generator.ts` 从地址库抽样并注入故障，**带标准答案**：
漏写省/市/区/小区、别名简称、历史老名、同音字/形近错别字、繁体、全角、噪声标点。
提供两个故障档位，避免用单一数字以偏概全：

- **realistic 真实分布档**：故障频率贴近真实手写面单（区漏写率仅约 1.5%、错别字约 6%）。
- **stress 激进压测档**：高比例故障（区漏写 8%、错别字 25%、噪声 30%），压测鲁棒性下限。

### 20 万条实测结果

| 指标 | realistic 真实档 | stress 压测档 | 验收线 |
| --- | --- | --- | --- |
| 省/市/区三级全对 | **≈ 99.4% ✅** | ≈ 95%（区显式 ≈99.8%） | ≥ 99% |
| 门牌级（楼栋/单元/房号全对） | **100% ✅** | 100% ✅ | ≥ 90% |
| 错误样本低置信度拦截召回 | **≈ 99.9%** | ≈ 97% | 越高越好 |
| 高置信度误放行率 | **≈ 0.0%** | < 0.5% | 越低越好 |
| 吞吐（单线程 Worker） | ≈ 500 条/秒 | ≈ 550 条/秒 | — |

说明：

- 信息充足（区写出、无故障）时街道准确率 100%；省、市显式准确率 100%。
- **最关键的质检能力是置信度校准**：解析错的面单几乎都被准确标成低置信度送人工格口，
  高置信度直接放行的错误接近 0，避免硬分错导致错分件。
- stress 档「整条链全对」低于真实档，主要来自 **漏写区且同城存在同名路** 的固有歧义
  （这类面单客观上信息不足，任何规则系统都无法 100% 消歧）。引擎通过小区锚点投票
  提升该场景，并对剩余歧义样本给低置信度转人工，而不是自信地分错。

## 数据说明

内置种子库（`core/data/seed.ts`）的省/市/区县用真实名称，街道/小区由词池程序化生成，
刻意制造大量跨区同名路、跨街同名小区、已撤销老区县、道路/小区更名，用于压测歧义与历史名能力。
真实部署时通过「标准地址库」页导入国标行政区划 CSV 即可替换，导入生成新版本且历史不丢。
